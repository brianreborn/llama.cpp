# Building **llama.cpp** on FreeBSD with Clang and ccache

This guide reproduces the successful build that was performed on the FreeBSD host `angel` (FreeBSD 15.1‑RELEASE-p6). It configures **CMake** to use the real Clang compiler while invoking **ccache** as a *compiler launcher* (instead of the ccache wrapper that replaces the compiler).

---
## Prerequisites

- **clang** (system default, e.g. `/usr/bin/clang` and `/usr/bin/clang++`).
- **ccache** (installed via `pkg install ccache`).
- Runtime libraries required by the project:
  ```bash
  sudo pkg install mpfr gmp openssl
  ```
- **CMake** (≥ 3.20) and **git**.

---
## Step‑by‑step build

```bash
# 1️⃣ Clone the desired pre‑release tag (b12244)
git clone --depth 1 --branch b12244 https://github.com/ggerganov/llama.cpp.git /home/green/llama-fbsd
cd /home/green/llama-fbsd

# 2️⃣ Create a clean build directory
mkdir -p build && cd build

# 3️⃣ Run CMake, explicitly selecting clang and telling CMake to use ccache as a launcher
cmake .. \
  -DCMAKE_C_COMPILER=/usr/bin/clang \
  -DCMAKE_CXX_COMPILER=/usr/bin/clang++ \
  -DCMAKE_C_COMPILER_LAUNCHER=ccache \
  -DCMAKE_CXX_COMPILER_LAUNCHER=ccache \
  -DCMAKE_BUILD_TYPE=Release

# 4️⃣ Compile (uses all available CPU cores)
cmake --build . -j$(nproc)

# 5️⃣ Verify the binary reports its version
./bin/llama --version
```

The output should look similar to:
```
version: 0.9.0-dev (build 1, commit d5bbcd1)
built with Clang 19.1.7 for FreeBSD amd64
```

## Why we set the *launcher* instead of using the wrapper

On FreeBSD the `ccache` package provides a **wrapper executable** named `ccache` that replaces the compiler in the `$PATH`. When CMake autodetects this wrapper as the compiler it ends up using the *ccache* binary as the actual compiler, which then fails because required libraries (e.g., `libmpfr.so.6`) are not linked.

By setting:
```cmake
-DCMAKE_C_COMPILER=/usr/bin/clang
-DCMAKE_CXX_COMPILER=/usr/bin/clang++
-DCMAKE_C_COMPILER_LAUNCHER=ccache
-DCMAKE_CXX_COMPILER_LAUNCHER=ccache
```
we:
1. Tell CMake to compile with the **real Clang** toolchain.
2. Instruct CMake to **invoke `ccache` as a launcher**, i.e., `ccache clang …`. This gives us all the caching benefits without the wrapper’s side‑effects.

```bash
cmake --preset freebsd-ccache
cmake --build --preset freebsd-ccache
```

## Cleaning up

To remove the build artefacts:
```bash
rm -rf build
```
If you no longer need the repository:
```bash
cd .. && rm -rf llama-fbsd
```
